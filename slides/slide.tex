\begin{frame}{The Claim}
    \centering
    \large\textit{``Privacy and LLM capability are compatible, under three conditions.''}
    \vspace{0.3cm}

    \begin{enumerate}
        \setlength{\itemsep}{0.22cm}
        \item[1.] The architecture itself keeps the model away from sensitive data.
        \item[2.] Detection recall is \textbf{measured} directly against real prompts.
        \item[3.] Business logic runs as \textbf{deterministic, auditable} server code.
    \end{enumerate}

    \vspace{0.25cm}
    \small Antares AI meets all three, in one workforce-management system, on the dataset this thesis tested.
\end{frame}

% -------------------------------------------------------
% Slide 3: Motivation
% -------------------------------------------------------
\begin{frame}{Motivation}
    \small
    \begin{itemize}
        \setlength{\itemsep}{0.2cm}
        \item Deloitte, \emph{State of Ethics and Trust in Technology} (approximately 1,848 professionals, September 2024): data privacy is the leading ethical concern regarding generative AI, cited by \textbf{40\%} of respondents, an increase from 25\% in 2023.
        \item Antares/Miorelli data is personnel-sensitive by construction: names, phone numbers, geographic coordinates, and absence records constitute personal data under the GDPR.
        \item A raw prompt such as \emph{``Trova i colleghi di Giulia Conti''}, transmitted to an external LLM, exposes a real name beyond the company boundary.
        \item The literature surveyed for this thesis treats rule-based detection and one-way redaction as separate techniques; no system reviewed combines local detection, reversible tokenisation, external semantic routing, and deterministic execution.
    \end{itemize}
\end{frame}

% -------------------------------------------------------
% Slide 4: Architecture, Components
% -------------------------------------------------------
\begin{frame}{Architecture, Components}
    Four cooperating runtime services:
    \vspace{0.3cm}
    \begin{itemize}
        \setlength{\itemsep}{0.3cm}
        \item \textbf{MCP Client}, builds the raw prompt, calls \texttt{/anonymize}, then \texttt{ask\_antares(user\_input, context\_id)}. Never sees PII again after that first call.
        \item \textbf{Anonymization API}, GLiNER-based detection, tokenisation, \texttt{/deanonymize-known}.
        \item \textbf{GLiNER Service}, stateless multilingual NER oracle, no knowledge of tokens or Redis.
        \item \textbf{MCP Server / JobTools}, Claude routes via \texttt{ask\_antares}, \texttt{JobTools} deanonymises and executes, server-local only.
    \end{itemize}
\end{frame}

% Slide 7: Methodology
% -------------------------------------------------------
\begin{frame}{Methodology}
    \small
    \begin{itemize}
        \setlength{\itemsep}{0.25cm}
        \item \textbf{Detection:} 50 hand-built Italian prompts, 82 labelled spans, coverage vs.\ strict metrics (CoNLL-2003 convention).
        \begin{itemize}
            \item[] \scriptsize\textit{``Trova i lavoratori pi\`u vicini al cantiere Bergamo Via della Fonda 5 Giulia S.r.l.\ entro 15 km''} $\rightarrow$ 3 tokens (\texttt{Bergamo}, \texttt{Via della Fonda}, \texttt{Giulia S.r.l.})
        \end{itemize}
        \item \textbf{Correctness:} differential testing, an independent reference implementation, zero shared code with the system under test.
        \item \textbf{PII boundary audit:} the exact Claude payload reconstructed client-side (no server instrumentation needed), scanned for 39 known real PII values across 50 prompts.
        \item \textbf{Routing:} log-diffing via timestamped report files, 21 prompts $\times$ 5 repetitions = 105 trials at temperature 1.0.
        \begin{itemize}
            \item[] \scriptsize Same canonical prompt $\rightarrow$ routed to \texttt{get\_nearest\_workers\_to\_cantiere}, detected via a new \texttt{UC-A}-tagged log file.
        \end{itemize}
    \end{itemize}
\end{frame}

% Slide 9: Limitations of the Evidence
% -------------------------------------------------------
\begin{frame}{Limitations of the Evidence}
    \scriptsize
    \begin{itemize}
        \setlength{\itemsep}{0.14cm}
        \item \textbf{Redis: no TTL; deanonymisation reads mappings via \texttt{Get}, leaving them in place.} The interface also defines a one-time-use \texttt{Pop}, which this path never calls. A single request can invoke the same tool multiple times against one context, the Bergamo prompt fragments into three location tokens, each requiring a deanonymisation call, so switching to \texttt{Pop} today would break multi-call correctness. A real, unresolved trade-off between reliability and data minimisation, requiring a deliberate design change to close.
        \item Local logs are stored unencrypted, without access control or a retention policy.
        \item The MCP transport lacks OAuth 2.1 authorisation, any client reaching the port is accepted.
        \item No adversarial prompt-injection test set was constructed; the structural defence is present but untested under active attack.
        \item Validation was conducted against a mock Miorelli backend; UC-C's absence/substitution branch never executed within the ticket window.
        \item The routing test set comprises 21 hand-built prompts. Consistency at temperature 1.0 held on this fixed set; whether it holds under arbitrary phrasing remains untested.
    \end{itemize}
\end{frame}
