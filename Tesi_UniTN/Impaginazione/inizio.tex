\begin{abstract}
Large language models show strong capabilities in understanding intent and semantic routing, but their adoption in business workflows remains limited by privacy and security requirements that general-purpose model APIs do not meet by default. This thesis investigates how language model based orchestration can be integrated into a real enterprise workflow while keeping personally identifiable information out of the model context, a design objective rather than a formal guarantee, since entity detection is probabilistic. The work is grounded in a specific workforce management domain within the Antares ERP ecosystem, where natural language requests must be mapped reliably to operational actions: locating nearby workers on client sites, identifying colleagues by proximity, and authorising holiday requests through their governing checks.

To answer this, the thesis proposes a privacy by design architecture built on the Model Context Protocol. User requests are pseudonymised before reaching the model: entities are detected locally, replaced with reversible tokens, and restored only server side, at the point where a business tool actually executes. The model itself sees only anonymised text and reasons over it to produce routing decisions, and it never receives the values behind the tokens. Entity detection uses GLiNER, a multilingual named entity recognition model chosen over rule based alternatives such as Microsoft Presidio after Presidio's recall on Italian business text proved insufficient for the company's use cases.

The approach draws on the broader state of the art in privacy preserving infrastructure. OpenAI's Privacy Filter, recently made open source, confirms that lightweight, on premise models used as preprocessing layers are an emerging pattern for containment, though it performs one way redaction and discards the mapping between placeholders and entities once masking is complete. Reversibility on its own is not unique to this work, as Presidio supports it through a dedicated operator pair. What this thesis contributes relative to that landscape is the combination of local detection, reversible typed tokens, external semantic routing, and deterministic server side execution operating together end to end, with deanonymisation controlled and confined to the protocol boundary, a distinction relevant under Article 4 of the GDPR, which classifies this processing as pseudonymisation rather than anonymisation.

The system was validated end to end against a mock replica of the production Miorelli backend. Across twelve test scenarios spanning three use cases, results matched an independently built reference implementation in every case. Semantic routing selected the correct tool in 95.2\% of 105 trials, with the one discrepancy traced to a logging artefact rather than a routing error. GLiNER reached 91.5\% recall on entity detection across 82 labelled spans in 50 test prompts, and the two payload leaks observed both traced to a detection miss, with no leak occurring through any other path.

These results have real limits. Detection recall sets the practical ceiling on the privacy guarantee, and it is not proof the system never leaks. The Redis context store retains token mappings for longer than the interface was designed to allow, since server side deanonymisation reads mappings rather than consuming them. The holiday request use case's authorisation paths were validated, but its absence coverage logic ran outside the mock dataset's active ticket window, so it was never exercised against a live absence. All validation uses a mock backend rather than the production system, a scope decision made with the host company to prioritise the privacy layer within the internship timeframe.

This work positions the Model Context Protocol as a practical interface standard for enterprise AI orchestration. The trade off is direct: added architectural complexity buys a measurable and testable privacy boundary, not a formal guarantee that no sensitive information can ever reach the model.

\noindent\textbf{Keywords:} LLM orchestration, Model Context Protocol (MCP), privacy-by-design, PII pseudonymisation, semantic routing, named entity recognition, GLiNER, enterprise AI security, GDPR compliance
\end{abstract}
